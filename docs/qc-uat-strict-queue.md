# Strict queue payload identity and replay — isolated candidate

Operator screenshot after b016ac3 confirms all 23 integrated QC photo transport and Firestore checks passed, exit 0, normal shutdown. The earlier 1000-expression failure is resolved for this suite; mock object storage only. Hosted UAT remains OFF.

Known gap: existing operational queue returns first job for an identity even if a later caller provides a different payload. Existing transport fast replay accepts matching save ID/revision without proof of identical payload. Both modules are also imported by feature-gated operational/pilot adapters. This checkpoint intentionally does not modify them or enable any feature. The new synthetic-only wrapper canonicalizes exact JSON payload (record, raw photo changes, action, base revision, uploader and scope), produces versioned SHA-256, ignores local creation timestamp, validates stored fingerprint if present, compares returned first row, and requires matching confirmed owner, status, identity and persisted fingerprint on both fast replay and commit response. Divergent jobs fail closed; existing pending synthetic rows can be compared from their bytes, but confirmed rows without fingerprint require review, never automatic backfill or deletion. No production queue migration, real DB write or storage access. Strict JSON and synthetic ID constraints are not claims about existing live DTO compatibility. Fingerprint is not authorization and is not a signature. Trusted server must independently bind it to the payload and persist with QC/Actual/audit, including concurrent replay. That is not implemented in this checkpoint. The injected enqueue must preserve first row atomically; the mock does not establish browser transaction guarantees.
